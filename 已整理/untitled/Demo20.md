# Demo20.java 内容总结

> 文件名是随手取的，以下按代码实际内容总结。

**主题：switch 的 case 穿透——月份判断季节**

- 用 Scanner 读入月份 month，用 `switch (month)` 判断季节：3、4、5 月打印“春”，6、7、8 月打印“夏”，9、10、11 月打印“秋”，12、1、2 月打印“冬”，其他值走 default 打印“输入的月份有误，请输入1-12之间的整数。”
- 写法上是 case 穿透的典型用法：同一季节的几个 case 堆叠在一起、中间不写 break，只在最后一个 case 后写一次 break。

**关键结论**

- case 穿透是“有意利用”而非 bug：3、4、5 月三个 case 共用同一段打印代码，命中其中任何一个都会落到“春”的打印语句再 break，比给每个月各写一遍打印简洁得多；与 Demo19 每个 case 各自打印、各自 break 的写法正好对照。
- 穿透的边界就是 break 的位置：每组最后一个 case 后的 break 决定了该组到此为止；如果漏掉组末的 break，春天会穿透成夏天，依此类推。
- 冬季一组是 12、1、2 月，顺序上 12 月写在 1、2 月前面也无妨——switch 按值匹配不按书写顺序，命中哪个 case 就从哪个 case 开始执行。

**笔试易错点**

- 分不清“有意穿透”和“漏写 break”：看题先判断是分组共用代码（本例）还是每 case 独立输出（Demo19）；前者中间无 break 是对的，后者漏 break 会多打印。
- default 的提示要与输入范围一致：本例 default 覆盖 0、负数、13 以上所有非法月份，提示“请输入1-12之间的整数”才算完整，只写“输入错误”在问答题里容易丢分。
- 资源关闭：本文件末尾有 sc.close()，比 Demo19 规范；考试写 Scanner 代码时记得收尾关闭，养成习惯。
