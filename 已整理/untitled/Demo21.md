# Demo21.java 内容总结

> 文件名是随手取的，以下按代码实际内容总结。

**主题：for 循环的几种基本用法（正序、倒序、累加、条件累加），外加一个未写完的水仙花数**

- 正序输出：`for (int i = 1; i <= 5; i++)` 打印 1、2、3、4、5。
- 倒序输出：`for (int i = 5; i >= 1; i--)` 打印 5、4、3、2、1。
- 求和：`sum` 从 0 开始，`for (int i = 1; i <= 5; i++) sum += i;`，结果为 15。
- 求偶数和：`sum1` 从 0 开始，遍历 1~100，用 `if (i % 2 == 0)` 筛出偶数累加，结果为 2550。
- 水仙花数只开了个头：声明了个位 a、十位 b、百位 c 三个变量，写了 `for (int i = 100; i <= 999; i++)` 的遍历骨架，但判断和输出都没写完。

**关键结论**

- for 循环三要素对照清晰：正序是“从小到大、i++、条件 i <= 上限”，倒序是“从大到小、i--、条件 i >= 下限”，两者只是方向和边界反过来，骨架完全相同。
- 累加题的固定套路是“循环外定义累加变量并初始化为 0，循环内符合条件才累加，循环结束后再一次性打印”——求和与求偶数和都是这个套路，后者只多了一步 `i % 2 == 0` 的筛选。
- 水仙花数的正确思路是：对每个三位数 i，个位 = i % 10、十位 = i / 10 % 10、百位 = i / 100，判断“个位³ + 十位³ + 百位³ == i”就打印；文件里已声明的 a、b、c 正是准备用来装这三个数字的。

**笔试易错点（本文件有一个实打实的编译错误，必须点出）**

- ⚠️ 当前文件**无法通过编译**：水仙花那段写的是 `if (i % 10)`——if 的条件必须是 boolean 类型，而 `i % 10` 是 int，必须写成带比较的布尔表达式，例如 `if (i % 10 == ...)`。另外这个 if 后面没有跟任何语句就直接换行接 `}`，即使条件改对了也还缺判断体和打印语句，整段水仙花逻辑目前是半成品。
- 求偶数和里 `i % 2 == 0` 才是“偶数”的判断；写成 `i % 2 == 1` 会筛出奇数，写成 `if (i % 2)` 则直接编译报错——这正是上面那个错误在别处的同款翻版，考试写 if 条件时先问自己“这是不是 boolean”。
- 累加变量必须在循环外初始化为 0：写在循环内会在每次迭代被重置为 0，最后结果永远是最后一项；打印也要放在循环外，放在循环内会把中间结果全部打出来。
- 边界取舍：1~5 求和用 `i <= 5`、1~100 用 `i <= 100`、三位数用 `100~999`，都是“含两端”；写成 `<` 就会漏掉最后一个数，是累加题最常见的差一错误。
