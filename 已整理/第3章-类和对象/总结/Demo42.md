# Demo42 总结

## 练的知识点
- **方法重载（overload）**：四个同名方法 `compare`，参数分别是 `int`、`byte`、`short`、`long` 各两个，方法体都是比较 `a == b` 返回布尔值，并在返回前打印自己的参数类型（"int"/"byte"/"short"/"long"），用来直观验证编译器到底匹配到了哪一个版本。
- **重载方法的调用与匹配**：`main` 里依次调用 `compare(10, 20)`、`compare((byte)10, (byte)20)`、`compare((short)10, (short)20)`、`compare(10L, 20L)`，四个调用分别命中四个版本。

## 关键结论
- 四个版本方法体逻辑完全一样，唯一区别是参数类型——重载的意义正在于此：调用者只记一个方法名 `compare`，传什么类型就自动匹配对应版本。
- 整数字面量默认是 `int`：`compare(10, 20)` 走的是 `int` 版；想调 `byte` 版必须显式窄化转换 `compare((byte)10, (byte)20)`，因为 int 到 byte 不会自动转换；`long` 版则靠 `L` 后缀 `compare(10L, 20L)`。
- 本例四个调用的比较结果全是 `false`（10 ≠ 20），所以完整运行输出是 8 行：int / false、byte / false、short / false、long / false 交替出现。

## 笔试易错点
- 不要只看返回值忽略方法体里先打印类型名那一行：每组调用输出两行（先是类型名，再是布尔结果），判运行结果题时两行都要写，漏一行即错。
- `==` 比较的是数值是否相等，返回的是 `boolean`（`true`/`false`），不是数值本身；不要把输出写成 `10`、`20` 之类。
- 本版四个 `compare` 都是 `static` 方法，所以能在静态的 `main` 里直接用方法名调用；旧版 Demo42（非静态、无调用）不能直接调用，两者对比正好是 static 与否的考点。
