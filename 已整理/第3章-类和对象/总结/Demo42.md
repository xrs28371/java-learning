# Demo42 总结

## 练的知识点
- **方法重载（overload）练第二遍**：四个同名方法 `compare`，参数分别是 `byte`、`short`、`int`、`long` 两两一组，都用三元运算符 `a > b ? a : b` 返回两者中的较大值，是 Demo41 的 `sum` 重载的换题型复现。

## 关键结论
- 四个版本方法体完全一样，唯一区别是参数类型——重载的意义正在于此：调用者只记一个方法名 `compare`，传什么类型就自动匹配对应版本。
- 三元运算符两边操作数类型相同时，结果就是该类型：`byte` 版里 `a > b ? a : b` 的结果仍是 `byte`，能直接 `return`，不需要强制转换；`short`、`int`、`long` 版同理。
- 重载匹配看实参类型：整数字面量默认是 `int`，所以 `compare(10, 20)` 走的是 `int` 版，不是 `byte`/`short` 版；想调 `byte` 版得显式转换，如 `compare((byte)10, (byte)20)`，因为 int 到 byte 的窄化转换不会自动发生。

## 笔试易错点
- **这份代码运行起来什么都不输出**：`main` 方法体是空的，四个 `compare` 方法定义了却一次都没被调用。笔试若问运行结果，答案是“无输出”，不是最大值。
- **这四个 `compare` 都不是静态方法**：没有 `static`，不能在静态的 `main` 里直接写 `compare(10, 20)` 调用；要先创建对象再调，如 `Demo42 d = new Demo42(); d.compare(10, 20);`。Demo41 的 `sum` 之所以能直接调用，正因为它加了 `static`——两者对比是本组题的考点。
- 同名不同参才叫重载：如果再写一个 `int compare(int a, int b)`（参数完全相同、只有返回值不同），编译直接报错。
