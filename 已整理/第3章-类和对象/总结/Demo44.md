# Demo44 总结

## 练的知识点
- **引用类型参数的传递**：`main` 里定义数组 `int arr[] = {10, 20, 30}`，打印 `arr[1]`，调用 `change(arr)`，`change` 里把 `arr[1]` 改成 200，再回到 `main` 打印 `arr[1]`，验证实参有没有被改动。
- **方法内修改数组元素**：`change` 方法体只有一句 `arr[1] = 200;`，改的是数组里的元素，不是数组变量本身。

## 关键结论
- Java 依然是按值传递，但引用类型传的是**引用（地址）的副本**：形参和实参是两个变量，却指向同一个数组对象，所以通过形参改元素，实参指向的数组也被改了。
- 运行输出是两行 `20`、`200`：调用前 `arr[1]` 是 20，`change` 把它改成 200 后，`main` 里再打印就是 200。
- 这正是 Demo43 的对照组：Demo43 传 int 副本改不动，Demo44 传数组引用副本、共享同一对象所以改得动；两题合起来就是“Java 只有值传递”这个考点的完整证据。

## 笔试易错点
- 不要因为“引用类型能改”就反推“Java 是引用传递”：传的仍是值的副本，只不过这个值是地址；如果 `change` 里是给形参重新赋值一个新数组（如 `arr = new int[]{1, 2, 3};`），实参 `arr` 仍指向旧数组，不会被替换——改元素和换对象是两回事，笔试常在这里设坑。
- 数组声明 `int arr[]` 写法合法但不推荐：规范写法是 `int[] arr`，把 `[]` 跟类型放一起；考试写代码时用 `int[] arr` 更稳妥。
- 文件开头 `import java.util.Arrays;` 根本没用到：代码里没有任何 `Arrays.` 调用，属于多余导入，虽然不影响编译运行，但属于应删掉的冗余；笔试填空/改错题里见到未使用的导入可直接指出。
