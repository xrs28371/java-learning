# Demo30.java 内容总结

> 文件名是随手取的，以下按代码实际内容总结。

**主题：数组的别名——两个变量指向同一个数组**

- 先给 `int[] arr = new int[3]` 赋值 100、200、300，打印数组名和三个元素确认。
- 关键一步：`int[] arr2 = arr;`——这不是复制一个新数组，而是让 arr2 和 arr 指向内存里同一个数组，之后通过 arr2 改值就是在改 arr 的内容。
- 通过 arr2 改值：`arr2[0] = 111; arr2[1] = 222; arr2[2] = 333;`，再打印时 arr[0] 也变成了 111（代码只打印了 arr[0]，但按别名原理 arr[1]、arr2[1] 同为 222，arr[2]、arr2[2] 同为 333）。
- 两次打印数组名得到的 `[I@...` 形式相同——arr 和 arr2 的引用相同，印证了它们是同一个数组。

**关键结论**

- 数组是引用类型：`arr2 = arr` 复制的是引用（地址），不是元素；此后 arr 和 arr2 是同一个数组的两个名字，改一边、两边都变。
- 想真正复制数组要用逐个赋值循环、`Arrays.copyOf` 或 `clone()`，直接用 `=` 赋值复制不到内容。
- 本例与 Demo29 正好对照：Demo29 的两个数组是 `new` 了两次、互不相干；本例只 `new` 了一次，第二个变量只是别名。

**笔试易错点**

- ⚠️ `arr2 = arr` 后“arr 的值变了”不是 bug，是别名机制：填空题问 arr[0] 是多少时，答案是经 arr2 改过的 111，不是原来的 100。
- ⚠️ 直接打印数组名只能看到 `[I@...`：arr 和 arr2 打印结果相同，说明引用相同；但只凭打印数组名看不到元素，元素必须逐个下标打印。
- 下标从 0 开始：长度为 3 的数组下标只能用 0、1、2，用到 arr[3] 会抛 ArrayIndexOutOfBoundsException。
- 别把“两个变量”当成“两个数组”：代码里 `new` 出现几次才有几个数组，本例只 `new` 一次，所以只有一个数组；数 `new` 的次数是判断别名最快的办法。
