# Demo29.java 内容总结

> 文件名是随手取的，以下按代码实际内容总结。

**主题：两个独立数组的创建、默认初始化与赋值前后对照**

- 创建了两个互不相干的数组：`int[] arr = new int[2]`（长度 2）和 `int[] arr2 = new int[3]`（长度 3），赋值前先打印、赋值后再打印一次，前后对照。
- 赋值前：两个数组的元素全是 int 默认值 0，即 arr[0]、arr[1] 都是 0，arr2[0]、arr2[2] 都是 0。
- 赋值后：`arr[0] = 100`、`arr2[0] = 200`、`arr2[2] = 300`，再打印时 arr[0] 是 100、arr2[0] 是 200、arr2[2] 是 300；没被赋值的 arr[1]、arr2[1] 仍是默认的 0。
- 两次打印数组名（`System.out.println(arr)`、`System.out.println(arr2)`）输出的都是类似 `[I@哈希码` 的引用形式，赋值前后不变——数组名打印的是引用，不是元素。

**关键结论**

- 数组是引用类型：`new` 出来的数组先按类型给默认值（int 是 0），不会出现“未初始化”的随机值。
- 两个数组是各自独立的：改 arr 不影响 arr2，改 arr2 也不影响 arr——这正是本例与“一个数组赋给另一个变量”（Demo30 的别名情形）的根本区别。
- 想看数组内容不能直接打印数组名，要逐个打印下标元素，或者用 `Arrays.toString(arr)`。

**笔试易错点**

- ⚠️ 直接 `System.out.println(arr)` 的输出不是元素：填空题问“输出什么”时，数组名直接打印得到的是 `[I@...` 这类引用形式，千万别写成元素值；且赋值前后它看起来不变，别误以为“赋值没生效”。
- ⚠️ 没赋值的元素不是“空”也不是报错：int 数组默认 0，本例 arr[1]、arr2[1] 始终是 0——题目常拿这个设问，答“没有值”就错了。
- 下标从 0 开始：arr 长度为 2，下标只能用 0、1，用到 arr[2] 就会越界；arr2 长度为 3，下标只能用 0、1、2。两个数组长度不同，越界边界也不一样，别按同一个长度数。
- 赋值前后对照是读题技巧：同一元素打印两次、值变了说明中间被赋值了，没变说明没被碰过——按这个思路追踪每个下标最稳。
