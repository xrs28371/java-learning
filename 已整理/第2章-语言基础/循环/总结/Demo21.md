# Demo21.java 内容总结

> 文件名是随手取的，以下按代码实际内容总结。

**主题：for 循环的几种基本用法（正序、倒序、累加、条件累加），最后是完整的水仙花数统计**

- 正序输出：`for (int i = 1; i <= 5; i++)` 打印 1、2、3、4、5。
- 倒序输出：`for (int i = 5; i >= 1; i--)` 打印 5、4、3、2、1。
- 求和：`sum` 从 0 开始，`for (int i = 1; i <= 5; i++) sum += i;`，结果为 15。
- 求偶数和：`sum1` 从 0 开始，遍历 1~100，用 `if (i % 2 == 0)` 筛出偶数累加，结果为 2550。
- 水仙花数：遍历 100~999，拆出个位、十位、百位，判断“个位³ + 十位³ + 百位³ == i”就打印，并用 `count` 统计个数后打印总数，结果应为 153、370、371、407，共 4 个。

**关键结论**

- for 循环三要素对照清晰：正序是“从小到大、i++、条件 i <= 上限”，倒序是“从大到小、i--、条件 i >= 下限”，两者只是方向和边界反过来，骨架完全相同。
- 累加题的固定套路是“循环外定义累加变量并初始化为 0，循环内符合条件才累加，循环结束后再一次性打印”——求和、求偶数和、水仙花计数都是这个套路。
- 水仙花数的拆位套路：个位 = i % 10、十位 = i / 10 % 10、百位 = i / 100，三者立方和等于原数即水仙花数。

**笔试易错点**

- ⚠️ 本轮已修正旧版的一个实打实逻辑错误：旧版百位写的是 `c = i % 100;`（取到的是后两位，不是百位），会让判断恒不成立、一个水仙花数都打不出来；现版已改成正确的 `c = i / 100;`。这是编译能过、结果全错的一类 bug，笔试和上机最坑。
- 求偶数和里 `i % 2 == 0` 才是“偶数”的判断；写成 `i % 2 == 1` 会筛出奇数，写成 `if (i % 2)` 则直接编译报错（if 条件必须是 boolean，不能是 int）。
- 累加变量必须在循环外初始化为 0：写在循环内会在每次迭代被重置为 0，最后结果永远是最后一项；打印也要放在循环外，放在循环内会把中间结果全部打出来。
- 边界取舍：1~5 求和用 `i <= 5`、1~100 用 `i <= 100`、三位数用 `100~999`，都是“含两端”；写成 `<` 就会漏掉最后一个数，是累加题最常见的差一错误。
