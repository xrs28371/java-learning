# Demo19 总结

## 练的知识点
- 方法重写（Override）的练习入口：配合 `Fu5`（父类）和 `Zi5`（子类），对比重写前后的调用效果。
- 父类对象与子类对象调用同一方法的差异：方法名相同，实际执行的是各自类里的版本。

## 关键结论
- 练习已补全：`main` 里先创建父类对象 `Fu5 f = new Fu5(); f.call("xrs")`，输出"给xrs打电话"；再创建子类对象 `Zi5 z = new Zi5(); z.call("xrs")`，输出"开启视频功能" + "给xrs打电话"。
- 两次调用的输出差异就是重写的直观效果：子类版本在父类功能前多了一步自己的内容（开启视频功能），父类功能本身通过 `super.call(name)` 保留下来了。
- 注释把重写场景说得很清楚：子类需要父类功能、但功能主体又有自己特有内容时才重写，不是把父类功能整个扔掉重写。

## 笔试易错点
- 重写的方法签名必须与父类一致（方法名、参数列表、返回值类型相同），否则不算重写。
- 注意区分两次调用的输出：`f.call()` 只有一行，`z.call()` 有两行；笔试常考"这段代码输出什么"，要按对象实际类型走，不要按方法名想当然。
- 多态延伸：如果写成 `Fu5 f = new Zi5(); f.call("xrs")`，编译看父类、运行看子类，实际执行的还是 `Zi5` 的版本。
